🏗️ Architecture

Understanding the architecture and design principles behind Spatial UI 3D.

📐 Architecture Overview

Spatial UI 3D is built on a layered architecture that separates concerns and promotes reusability:

┌─────────────────────────────────────────────┐
│         🎨 Component Layer                  │
│  Button3D, Toggle3D, Slider3D, etc.        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│         🏗️ Core Layer                       │
│  BaseControl3D, ControlRegistry,           │
│  RoomManager, Scene3D                      │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│         🛠️ Utility Layer                    │
│  HTMLOverlay, MarkdownRenderer,            │
│  SacredGeometry                            │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│         🌐 Three.js Foundation              │
│  Scene, Camera, Renderer, Controls         │
└─────────────────────────────────────────────┘

📚 Architecture Layers

1. Three.js Foundation

Purpose: Provides the underlying 3D rendering engine.

Key Components:

  • THREE.Scene - 3D scene container
  • THREE.PerspectiveCamera - Camera view
  • THREE.WebGLRenderer - WebGL rendering
  • OrbitControls - Camera navigation
  • TransformControls - Object manipulation

Why: Three.js provides battle-tested 3D rendering with excellent performance and broad browser support.

2. Utility Layer

Purpose: Shared utilities and helpers used across the framework.

Key Components:

  • HTMLOverlay - Manages HTML elements in 3D space using CSS3DRenderer
  • MarkdownRenderer - Converts markdown to HTML
  • SacredGeometry - Creates sacred geometry patterns

Why: Centralizes common functionality to avoid duplication and ensure consistency.

3. Core Layer

Purpose: Core framework classes that provide foundation for all components.

Key Components:

  • Scene3D - Main scene manager, handles setup and rendering
  • BaseControl3D - Abstract base class for all 3D controls
  • ControlRegistry - Global registry for control management
  • RoomManager - Environment/background management

Why: Provides consistent behavior, reduces boilerplate, and enables global features like edit mode.

4. Component Layer

Purpose: User-facing UI components that extend BaseControl3D.

Key Categories:

  • Core: Button3D, Toggle3D, Slider3D, TextInput3D, etc.
  • Advanced:
    • MagneticCard3D - Physics-based tilt interactions.
    • PortalCard3D - Multi-scene rendering via RenderTargets.
    • VolumetricCard3D - Integration with 3D models (GLTF).
    • HaloCard3D - Dynamic billboarding and anchor-following.
  • Generative: AIPortal3D - Environment traversal logic and custom Shaders.

Why: Provides a modular ecosystem where components can be swapped or combined for complex spatial experiences.

🌌 Advanced Architectural Patterns

1. Render-Target Viewports (Portals)

Used in PortalCard3D and AIPortal3D to create "windows" into separate dimensions without affecting the main scene's state.

2. Physics-Based Lerping (Magnetic)

Physics-like movement in MagneticCard3D is achieved via high-frequency LERPing and damping factors applied to local rotations.

3. World-Swapper Logic

A declarative pattern where a component (like AIPortal3D) can coordinate with the RoomManager to hot-swap environment variables (skybox, fog, lighting) based on camera proximity.

🌸 Sacred Design Principles

1. 🧘 Tietoisuus-ensimmäinen (Consciousness-First)

Every component serves spatial wisdom. 3D space provides context and meaning, not just visual flair.

Implementation:

  • Depth conveys hierarchy and importance
  • Position indicates relationships
  • Movement draws attention intentionally

2. 💚 Yhteisön parantaminen (Community Healing)

Accessible design reduces cognitive load. Calm design prevents overwhelm.

Implementation:

  • Smooth animations reduce jarring transitions
  • Clear affordances show what's interactive
  • Intentional friction prevents accidents

3. 🌌 Spatiaalinen viisaus (Spatial Wisdom)

3D space is core to the experience, not an afterthought.

Implementation:

  • Three geometry modes (box, sphere, sacred)
  • Depth-based organization
  • Natural camera navigation

4. ♾️ Ääretön yhteistyö (Infinite Collaboration)

Components work together harmoniously. Extensible and composable architecture.

Implementation:

  • Shared base class ensures consistency
  • ControlRegistry enables global coordination
  • Event system allows component communication

🎯 Design Patterns

Inheritance Pattern

All components extend BaseControl3D to inherit common functionality:

JavaScript
export class MyControl extends BaseControl3D {
    constructor(scene, camera, position, config) {
        super(scene, camera, position, config);
        // Component-specific initialization
    }
    
    create() {
        // Create 3D geometry
    }
    
    update() {
        // Update state each frame
    }
}

Benefits: Consistent API, shared tooltip system, automatic registration, edit mode support.

Registry Pattern

ControlRegistry maintains a global list of all controls:

JavaScript
// Automatic registration in BaseControl3D constructor
ControlRegistry.register(this);

// Global operations
ControlRegistry.setEditMode(true);
ControlRegistry.getAll().forEach(control => control.update());

Benefits: Centralized control management, global edit mode, bulk operations.

Mode System Pattern

Components support multiple geometry modes for visual variety:

JavaScript
this.modes = ['box', 'sphere', 'sacred'];
this.mode = config.mode || 0;

switch (this.modes[this.mode]) {
    case 'box':
        geometry = new THREE.BoxGeometry(...);
        break;
    case 'sphere':
        geometry = new THREE.SphereGeometry(...);
        break;
    case 'sacred':
        geometry = createSacredGeometry(...);
        break;
}

Benefits: Visual consistency, easy theming, sacred geometry support.

HTML Overlay Pattern

Complex UI elements use HTML overlays via CSS3DRenderer:

JavaScript
const htmlOverlay = getHTMLOverlay();
htmlOverlay.createOverlay(id, element, position, {
    scale: [0.01, 0.01, 0.01],
    className: 'spatial-overlay'
});

Benefits: Rich text rendering, form inputs, accessibility, familiar HTML/CSS.

Event Callback Pattern

Components use callbacks for user interactions:

JavaScript
new Button3D(scene, camera, position, {
    onClick: (button) => { /* handle click */ },
    onHover: (button) => { /* handle hover */ },
    onHoverEnd: (button) => { /* handle hover end */ }
});

Benefits: Decoupled logic, flexible integration, reactive updates.

🚀 Performance Considerations

  • ✅ Efficient Raycasting: Only interactive objects are raycast-tested
  • ✅ Texture Reuse: Gradients and textures are cached when possible
  • ✅ Smooth Animations: Lerp-based animations prevent jarring updates
  • ✅ Lazy Updates: Components only update when visible or changed
  • ✅ Memory Management: dispose() methods clean up resources
  • ✅ Shadow Optimization: Selective shadow casting/receiving

🔮 Future Architecture

Planned architectural improvements:

  • 🔄 TypeScript Migration: Type safety and better DX
  • 🎯 Component Composition: Nest components within each other
  • 🌊 State Management: Reactive state system
  • 🎨 Theme System: Global theming and styling
  • 📦 Module Bundling: Optimized build system
  • 🧪 Testing Framework: Unit and E2E tests
