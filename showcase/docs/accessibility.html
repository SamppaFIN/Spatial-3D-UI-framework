♿ Accessibility

Making spatial interfaces accessible to everyone.

WCAG 2.1 Level AA Partial Support

🌍 Accessibility Philosophy

Spatial UI 3D is built with accessibility in mind, though 3D interfaces present unique challenges. Our approach:

  • 💚 Community Healing: Reduce cognitive load through calm, intentional design
  • 🎯 Progressive Enhancement: Core functionality works without 3D when possible
  • 🔍 Clear Affordances: Visual cues show what's interactive
  • ⌨️ Keyboard Support: All interactive elements are keyboard-accessible
  • 📱 Responsive Design: Works across devices and screen sizes

✨ Accessibility Features

⌨️ Keyboard Navigation

Status: ✅ Supported

All interactive components support keyboard interaction:

  • Tab - Navigate between controls
  • Enter/Space - Activate buttons and toggles
  • Arrow Keys - Adjust sliders
  • Esc - Close modals
JavaScript
// TextInput3D automatically focuses on click
const input = new TextInput3D(scene, camera, [0, 0, 0], {
    placeholder: 'Type here...',
    renderer: renderer
});

// Focus programmatically
input.focus();

🎨 Color Contrast

Status: ✅ WCAG AA Compliant

Default color schemes meet WCAG 2.1 Level AA contrast requirements:

  • Text: 4.5:1 minimum contrast ratio
  • Interactive elements: 3:1 minimum contrast ratio
  • Focus indicators: High-contrast borders
JavaScript
// Use high-contrast colors
const button = new Button3D(scene, camera, [0, 0, 0], {
    label: 'Submit',
    color: 0x4ecdc4, // Cyan - good contrast
    textColor: 0x000000, // Black text on cyan
    renderer: renderer
});

😇 Accessible Labels (HaloCard3D)

Status: ✅ Supported

Use HaloCard3D to provide always-visible, billboarding labels for 3D objects that might be difficult to identify from certain angles.

  • Always faces the camera for maximum legibility.
  • Anchors to complex shapes without clipping.
  • Supports high-contrast text and icons.

💡 Tooltips & Labels

Status: ✅ Supported

All components support descriptive tooltips and labels:

  • Tooltips provide context on hover
  • Labels identify control purpose
  • Markdown support for rich descriptions
JavaScript
const slider = new Slider3D(scene, camera, [0, 0, 0], {
    label: 'Volume',
    tooltip: {
        content: '**Volume Control** 🔊\\n\\nAdjust audio volume from 0-100',
        position: 'top'
    },
    renderer: renderer
});

🎭 Focus Indicators

Status: ✅ Supported

Clear visual feedback for focused elements:

  • Scale animations on hover
  • Emissive glow on focus
  • Color changes for active states
JavaScript
// TextInput3D shows focus state
const input = new TextInput3D(scene, camera, [0, 0, 0], {
    focusColor: 0x6bb6ff, // Bright blue when focused
    borderColor: 0x5a5a8e, // Dimmer when not focused
    renderer: renderer
});

📱 Responsive Design

Status: ✅ Supported

Components adapt to different screen sizes:

  • Touch-friendly hit targets (minimum 44x44px)
  • Responsive canvas sizing
  • Mobile-optimized controls
JavaScript
// Handle resize
window.addEventListener('resize', () => {
    const width = canvas.clientWidth;
    const height = canvas.clientHeight;
    camera.aspect = width / height;
    camera.updateProjectionMatrix();
    renderer.setSize(width, height);
});

🎬 Reduced Motion

Status: ⚠️ Partial Support

Respect user's motion preferences:

  • Smooth, intentional animations
  • No auto-playing animations
  • User-controlled camera movement
JavaScript
// Check for reduced motion preference
const prefersReducedMotion = window.matchMedia(
    '(prefers-reduced-motion: reduce)'
).matches;

// Adjust animation speed
const animationSpeed = prefersReducedMotion ? 0.5 : 0.15;

📋 Best Practices

1. Always Provide Text Alternatives

JavaScript
// ✅ Good: Descriptive label and tooltip
const button = new Button3D(scene, camera, [0, 0, 0], {
    label: 'Save Changes',
    tooltip: {
        content: '**Save** 💾\\n\\nSave your changes to the server'
    },
    renderer: renderer
});

// ❌ Bad: No context
const button = new Button3D(scene, camera, [0, 0, 0], {
    label: '✓',
    renderer: renderer
});

2. Use Semantic Callbacks

JavaScript
// ✅ Good: Clear callback names
const form = {
    onSubmit: (data) => saveToServer(data),
    onCancel: () => resetForm(),
    onError: (error) => showErrorMessage(error)
};

// Use in components
const submitBtn = new Button3D(scene, camera, [0, 0, 0], {
    label: 'Submit',
    onClick: form.onSubmit,
    renderer: renderer
});

3. Provide Visual Feedback

JavaScript
// ✅ Good: Visual state changes
const toggle = new Toggle3D(scene, camera, [0, 0, 0], {
    label: 'Dark Mode',
    onColor: 0x4ecdc4,  // Bright when on
    offColor: 0x666666, // Dim when off
    renderer: renderer,
    onClick: (toggle) => {
        // Update UI to reflect state
        updateTheme(toggle.isOn ? 'dark' : 'light');
    }
});

4. Test with Keyboard Only

Ensure all functionality is accessible without a mouse:

  • Tab through all interactive elements
  • Activate controls with Enter/Space
  • Navigate sliders with arrow keys
  • Close modals with Escape

5. Use High Contrast Colors

JavaScript
// ✅ Good: High contrast
const colors = {
    primary: 0x4ecdc4,   // Cyan
    secondary: 0x6bb6ff, // Blue
    success: 0x48bb78,   // Green
    warning: 0xffaa00,   // Orange
    danger: 0xff6b9d     // Pink
};

// ❌ Bad: Low contrast
const colors = {
    primary: 0x333333,   // Dark gray
    secondary: 0x444444  // Slightly less dark gray
};

⚠️ Known Limitations

Screen Reader Support

Status: Limited

Issue: 3D WebGL content is not natively accessible to screen readers.

Workaround:

  • Use HTML overlays for text content (TextInput3D, TextDisplay3D)
  • Provide alternative 2D views for critical functionality
  • Add ARIA labels to canvas elements
HTML
<canvas 
    id="scene" 
    role="application"
    aria-label="3D spatial interface"
    aria-describedby="scene-description"
></canvas>
<div id="scene-description" class="sr-only">
    Interactive 3D interface with buttons, sliders, and controls.
    Use Tab to navigate, Enter to activate.
</div>

Motion Sickness

Status: Potential Issue

Issue: 3D camera movement can cause motion sickness in some users.

Mitigation:

  • Smooth, controlled camera movements
  • User-controlled navigation (no auto-rotation)
  • Option to disable 3D and use 2D fallback
  • Respect prefers-reduced-motion

Performance on Low-End Devices

Status: Potential Issue

Issue: WebGL rendering can be slow on older devices.

Mitigation:

  • Optimize geometry and texture usage
  • Provide quality settings
  • Detect device capabilities and adjust
  • Offer 2D fallback mode
